## Problems and fixes
| Problem | What caused it | How we fixed it |
|---|---|---|
| A script would crash if no arm answered | `XArmAPI(ip)` throws an error (an "exception") when nothing is at that IP address | The scripts wrap the connection in `try/except` and print a friendly message instead |
| A MacBook has no Ethernet port | — | A USB-C to Ethernet adapter, set by hand to 192.168.1.100 |
| `set_position` could send the arm somewhere unexpected if you leave values out | It fills in missing values from the *last commanded* position, not from where the arm is now | Always pass all six values, or use `relative=True` |

## Key idea (the 20% that mattered today)
Before any code moves the arm, test **without** moving it. `01_hello_arm.py` only reads the arm's position, so it's the safe way to prove the cable and IP address work. Every real move then follows the same 4-line get-ready routine (clear errors → power on the motors → pick a mode → set "ready"), runs slowly at first, and has someone's hand near the E-stop (the big red emergency-stop button). Every command answers with a code: **0 means OK.**
