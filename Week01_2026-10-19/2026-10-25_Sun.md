## Problems and fixes
| Problem | What caused it | How we fixed it |
|---|---|---|
| Teleop v1: the arm kept moving after we let go | An arm error switched it out of teleop mode. In normal mode, every new target waits in a queue behind the old ones. | Version 2 and later use **mode 7**, where each new target *replaces* the last one. Letting go stops the arm at once, and the program quits on any arm error. |
| School Wi-Fi blocked the Quest from talking to the computer | School networks often block devices from talking to each other | Everything by cable. The Quest uses a Link cable to the PC. |
| The Link cable dropped every 1–4 minutes | Windows' USB power saving cuts the connection | Turned USB power saving off with `powercfg`. Not confirmed yet that this fixed it. |
| Smart App Control blocked the Python that `uv venv` made | That Python launcher isn't digitally signed | Built the environment with `python -m venv` instead |
| Smart App Control blocked PyTorch | 12 of PyTorch's files aren't signed | Run LeRobot and SmolVLA in Ubuntu (WSL) instead |
| Ubuntu (WSL) can't see USB cameras | WSL doesn't get USB devices by default | Split the work: Windows records (camera + arm), Ubuntu trains |
| The SDK printed warnings on every run | Its Blockly tools have old-style code | Ran `python -m compileall` on it once |
| `git push` couldn't ask for the GitHub login | Claude's command window can't show sign-in pop-ups | Ran the push in the Terminal panel and signed in through the browser |

## Key idea (the 20% that mattered today)
**For live control, tell the arm "go here *instead*," not "go here *next*."** In normal mode the arm finishes every move in its queue, like a line at a cafeteria. When your hand sends 30 targets a second, that line grows, and the arm is still working through old targets after you've stopped. Mode 7 throws away the old target whenever a new one arrives, so the arm always chases your hand's *latest* position, and letting go really means stop. Behind that we stacked safety layers (workspace limits, the arm's own fence and speed cap, a dead-man timer, an on/off button) so one bug can't cause a crash.
